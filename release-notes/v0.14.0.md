# Mindflow v0.14.0

**Released:** 2026-11-07

## What's new

- **Dictation's microphone is yours to choose, and it is named in the menu bar.** Open the Mindflow popover and the microphone row tells you exactly which input dictation will record from. You can pick any input on your Mac, or leave it following whatever System Settings › Sound › Input points at, which is what it has always done. If the microphone you picked is not connected, Mindflow says so and names the one it is using instead, rather than quietly recording from something else. This covers dictation only — meetings still record from your system input, and neither one ever changes your system-wide sound settings.

- **The menu bar now says "Preparing audio…" while a recording is starting.** It used to say it was recording from the moment you clicked, which was not yet true: macOS can take a while to hand over the microphone, and anything you said in that window was not captured. Mindflow now shows you the difference between getting ready and listening, so you know when to start talking. Anything watching Mindflow's status gets the same correction, including AI assistants — they are told a recording is live only once audio is genuinely flowing.

- **Pressing Escape during dictation now also copies what you said to your clipboard.** Escape still means "do not paste this" rather than "forget it happened": the text is saved to your dictation History as before, and now it is one ⌘V away as well.

## Fixes

- **Transcribing a file in Arabic no longer fails at the finish line.** A long recording could run for minutes of processing and then stop with a "couldn't be read" error, losing the whole job — a real 47-minute Arabic file failed exactly that way. One damaged character in the speech engine's output was enough to make Mindflow reject the entire transcript. It now repairs the damage and keeps the transcript. This was never Arabic-specific: Chinese, Japanese, Korean, Russian, Hebrew, Greek, Thai, accented European text and emoji could all trigger it, and whether it happened at all varied from one recording to the next, so it was easy to mistake for bad luck.

- **A dictation can no longer come back empty because of one bad character.** The same kind of damage on the dictation path used to discard everything you had just said and leave you with nothing and no explanation. At worst you now get one garbled character in an otherwise complete sentence.

- **Mindflow no longer declares itself broken at launch.** On startup it checked that its speech engine could run, gave it fifteen seconds, killed it when it had not answered in time, and then reported its own kill back to you as "the bundled binary is likely broken — reinstalling Mindflow usually fixes this", before quitting. The engine was healthy. The first time your Mac runs it, it spends about twenty seconds building its code for your graphics hardware, and it can need to do that again later — after a system update, for instance. Reinstalling could not help, because every launch killed that work before it could finish. The check no longer runs against a stopwatch: it asks whether the engine runs, not how quickly it answers.

- **Quitting Mindflow can no longer leave it frozen.** When something was still in flight, Mindflow asked whether you really meant to quit — but if nothing could show you that question, for example when your screen was locked, it waited indefinitely for an answer that could never come and stopped responding for minutes. It now recognises when nobody can answer and goes straight to finishing your work and quitting, and the question has a time limit in every other case.

- **Asking an AI assistant to transcribe a file with a particular speech model now uses that model.** Mindflow could quietly substitute a different one, so you got a result from a model you had not asked for and no way to tell.

- **When dictation hears nothing, it names the microphone it was listening to.** The message used to leave you guessing, which mattered most in exactly the situation it was reporting: the wrong input being open.

- **Dictation settings showed the wrong default shortcut.** The default is ⌃⌥Space (Control + Option + Space), not the four-key combination the settings screen displayed throughout v0.13.

- **VoiceOver no longer announces that Mindflow is reconnecting during periods when nothing is being retried.**

## Under the hood

- The first recording after you launch Mindflow is slow to start: roughly 40 seconds on a Mac with a lot of audio devices connected, and longer again with a Bluetooth headset. Every recording after that one, in the same session, starts within a few seconds. That wait is macOS bringing up its audio path, not Mindflow holding things up, and there is no part of it we are allowed to warm up in advance. The new "Preparing audio…" state exists so the wait is visible instead of silent.

- If you installed v0.13.5, this release supersedes it. It was the current version for a single day in September, but until today it was also what the Download button on the website handed you, so you may be running it without having chosen it. That version picked a microphone for dictation on your behalf and, on a Mac with many inputs, could land on something you would never have picked — a webcam microphone in the reported case — which is why it was withdrawn the next day. The microphone selector above is its replacement: nothing chooses for you now; Mindflow follows your system input unless you name a device yourself.

- If you use Mindflow's tools from Claude Code, Cursor or another AI assistant, restart that client after updating. The client starts Mindflow's tool server itself, so until it restarts it keeps running the previous version's copy.

- This build is compiled against the current macOS SDK, so the app renders with the current system appearance.
